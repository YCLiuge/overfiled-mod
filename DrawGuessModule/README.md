# 你画我猜与频道画架 · 1.1.2

本版将普通画架改为频道内独立的个人画架，并改用画手自己输入的题目。普通画架只有创建者可以画；游戏中，房主选定的画架由当前画手作画，其他玩家观看和猜词。

## 更新要求

本次增加了频道画架传输协议 `BOARD / BOARDMSG`，必须配套更新：

1. 退出游戏，将构建产物 `GameMods/Mods/mod.dll` 替换到游戏的 `Mods/mod.dll`，再启动游戏。
2. 更新中继服务器的完整发布文件并重新启动；服务端仍使用 .NET 9。
3. 每位玩家更新 `DrawGuessModule.dll`（版本 1.1.2）。宿主更新并重启后，后续绘画模块仍可热更新。

旧宿主缺少频道广播 API 时，模块提示更新宿主并重启。只有连接同一新版中继、处于同一游戏频道、加载新版绘画模块的玩家才会生成同步画架。启动本机服务不代表已经部署公网预设服务。

## 使用流程

### 普通画架

1. 使用 `net` / `dg connect` 连接宿主网络，等待频道同步；按 F8 打开绘画面板。
2. 点击“放置画架”或输入 `dg board`，在自己前方创建画架。每个连接拥有一个画架，再次放置会移动它。
3. 创建后进入自由绘画，自己的画架只能由自己修改；同频道其他玩家自动收到画架、位置和公开笔迹，无须先加入房间。
4. 隐藏面板后，按住左 Alt 或右 Alt，再用鼠标左键点击别人的画架打开只读观看；普通点击不触发。再次 Alt＋点击自己的画架或重新放置自己的画架可返回自己的画布。
5. 离线时仍可使用 `dg mode free` 绘画和 `dg save 名称` 保存 PNG；离线画布在本次模块会话中保留。联网创建画架需要有效游戏频道。

每架独立持有像素、撤销缓存、纹理和材质，场景显示不会共用同一张画。频道画架优先复用游戏已加载的“家具店画架”原版模型，每架使用独立显示副本和绘画贴图；副本在未激活时移除家具行为及物理组件，不注册实际家具。未找到模型时暂用备用画架，原版模型加载后自动替换。

普通自由绘画不再创建多人共同作画的自由画室。`dg host` 用于你画我猜游戏；自由模式会提示切换玩法。

### 创建与加入游戏

1. 房主先执行 `dg board` 创建自己的画架，然后选择“你画我猜”（`dg mode guess`）。
2. 填房间名并点击“创建房间”，或输入 `dg host 房间名`。没有自己的画架时拒绝建房，并提示先放置画架。
3. 房主的画架显示房主、游戏房间和“Alt＋点击加入”标记。其他玩家隐藏面板后，按住 Alt 点击这个画架加入。
4. 至少两人后房主开始游戏。游戏共用房主的这一个画架，只允许当前画手作画；其他普通画架保留创建者独占权限。
5. 每轮先等待当轮画手在右侧输入 1–16 字题目，点击“提交题目，开始作画”。提交前不能画、不能猜；提交成功才开始本轮作画倒计时。
6. 其他玩家在右侧提交答案。题目只出现在画手的私有面板，场景标签和画架不显示答案；揭晓阶段才公开。
7. 画手 30 秒内未出题则跳过这一轮；默认揭晓 5 秒后轮换。房主可按“下一轮”跳过。新一轮必须重新出题。

点击加入会同时核对画架的创建者身份和房间实例，避免同名房间或旧画架误加入。兼容命令 `dg join 房间名 [房主名]` 也必须先发现该房间已经绑定的频道画架，不能绕过画架绑定创建或接管房间。

## 操作和命令

F8 显示或隐藏面板，Esc 隐藏；面板隐藏时按住左 Alt 或右 Alt，再用鼠标左键点击场景画架。放置位置约在玩家前方两米，同步玩家须处在同一场景坐标空间。

| 命令 | 行为 |
| --- | --- |
| `paint` / `dg` | 打开面板 |
| `dg board` | 创建或移动自己的频道画架 |
| `dg mode free` | 自由绘画；切换会离开当前游戏房间 |
| `dg mode guess` | 你画我猜；之后可创建游戏房间 |
| `dg host 房间名` | 将自己的画架绑定新游戏房间 |
| `dg start 1 60` | 房主开局；每人 1–3 轮，每轮作画 30–180 秒 |
| `dg word 苹果` | 当前画手在选题阶段提交题目 |
| `dg guess 苹果` | 当前猜题者提交答案 |
| `dg next` | 房主跳过本轮或揭晓等待 |
| `dg leave` | 离开游戏房间，房主离开会关闭房间 |
| `dg save 名称` | 自由模式将当前已接受画布导出 PNG |
| `dg status` | 查看连接、房间和场景画架状态 |
| `dg sync` | 请求当前游戏状态和回放 |
| `dg connect local` | 使用角色名连接 `127.0.0.1:9000` |
| `dg connect public` | 切换公网预设 |
| `dg connect 主机 端口` | 改用指定中继服务器 |

房间名和角色名不含空白。PNG 输出到游戏运行目录 `UserData/DrawGuess/Paintings`，名称会过滤路径字符并附加唯一后缀，避免覆盖；不向网络上传图片。

## 同步与生命周期

所有游戏联机复用 `mod.st.NetChater.Instance` 的同一 `ChatClient`，模块不会创建独立 TCP 连接。宿主负责频道与连接生命周期；卸载绘画模块只释放自己的房间、订阅、队列和 Unity 资源。

服务器把连接 SessionId 注入频道画架消息，画架身份使用这个认证值，而非正文中自报的身份。频道广播要求连接只加入当前一个频道。普通画架不接受他人绘画请求；游戏绘画仍由房主权威校验当前画手、回合、操作序号和房间实例。

画布最多保留 1000 条规范化笔迹。频道画架分批回放，每批最多 48 条，完整接收后替换显示，防止半幅回放覆盖完整图；不完整、旧版本及越序分片被拒绝。新进入频道者请求画架公告与回放，画架持有者定期发送存活公告。其他人离开、断网或卸载后，旧画架最长约 20 秒未收到公告会清理。切换自己的频道立即清除旧频道画架和房间。

普通频道画架同步会受画布大小、分批发送和网络条件影响；游戏房间内继续使用已有的实时笔迹通道。频道里旁观但未加入游戏的人仍通过公开画架回放看到游戏笔迹。

房主进程是游戏权威端，会持有当前答案以便判题。正常客户端只给当轮画手私有快照发送题目，猜题者的状态和频道画架协议都不包含答案。没有内置随机题库作为生产默认出题来源。

## 构建和验证

```powershell
$env:MSBuildEnableWorkloadResolver='false'
dotnet build .\mod\mod.sln -c Release -p:Platform=x64

dotnet run --project .\tools\DrawGuessVerification\DrawGuessVerification.csproj -c Release
dotnet run --project .\tools\DrawGuessIntegrationVerification\Verify.csproj -c Release
```

输出模块及清单在 `GameMods/Mods`，服务端构建在 `服务器/Chat.Server/bin/Release/net9.0`。在运行中替换宿主不生效，必须退出游戏后替换并重启；公网中继需要在实际服务端部署配套构建。

核心规则已验证 100 项，包括画手身份、题目格式、重复或迟到提交、计时起点、保密、超时跳过、断线和轮换。多客户端 TCP 联调使用真实本机中继、生产运行时和测试面板适配器；测试结果以实际运行输出为准。旧版多人自由画室和实机截图不能证明本版多画架行为，本版不宣称已在多个完整游戏进程或公网服务完成实测。
