基线为 BanterSR/Lolo 375423e8c0806bfe8804001ac46d8bc371843045；客户端和资源版本保持原配置。

## 星云树徽章页与节点激活（local-sandbox-17）

- MoonStone 徽章页与 PlayerAbility 能力列表分别同步。徽章页使用 StoneAreaData.ID 作为网络 Page，通过 UnlockID 查找实际节点配置，列表按 SceneID 过滤，避免把配置组 ID 当作页号。
- 沙盒打开页面时幂等补齐 8 页、198 个有效节点，跳过布局占位格，并在现有玩家存档内保存节点状态；保留其他存档键和已有领奖记录。
- 注册列表、节点激活、整页领奖及成就领奖四个请求的处理器，所有请求均回复对应 PacketId。重复激活不扣材料、不重复发奖；奖励池映射尚未验证的领奖明确返回失败。
- 回归测试覆盖配置完整性、Page 与 SceneID 不同的情况、隔离 SQLite 保存重载、重复操作、无效节点、协议序列化与回包。全量 Go 测试通过；实际客户端引导及点击效果仍需实机确认。

## 账号密码与自动登录（local-sandbox-16）

- SDK V1/V2 兼容 `auth_token` 与 `authToken`；自动登录按数据库持久 AuthToken 精确验证，成功后刷新登录凭据。已有 token 内的时间原本未参与过期判断，不能将本次问题归因于十分钟超时；数据库凭据验证也允许保存的旧 token 在服务端密钥变化后恢复登录。
- 账号密码入口拒绝空账号、空密码及错误密码，并返回对应原因；首次输入新账号仍可创建，已注册账号的密码不会被后续输入覆盖。新账号分配避免复用旧角色的 SDK UID；checkLogin 校验 UID 与令牌归属。
- 提供离线恢复脚本：只给缺少 OFQuick 的旧 SDK UID 新增恢复凭据，保持 OFUser、OFGame 及已有账号记录不变；先备份再事务写入，明文报告留在本地私密目录。历史网关/探针身份不等同于真实玩家。
- 自动测试使用临时数据库，覆盖恢复前后角色映射、已有密码、用户名碰撞、失败回滚、重复执行，以及真实 SDK 加密请求的账号登录和自动登录。

## 好友申请与五个染色方案（local-sandbox-15）

- 好友申请列表读取收到的申请，并显示申请者资料；修正处理申请的双方参数顺序。同意及互相申请成功后，在线双方收到好友变更通知；拒绝移除待处理申请。
- 区分已是好友、申请待处理、自申请和不存在的目标；持久化失败时不返回成功或发送成功通知。接受申请事务内写入双向关系，删除时移除双向记录；双方黑名单参与申请校验。
- 沙盒登录时，为已有服装补齐界面中五个方案（索引0至4）的解锁状态；只新增缺失方案、设置解锁标记，保留原配色及历史额外方案。重新登录即可收到完整方案数据。
- 服装下发的方案按索引排序，避免 Go map 随机遍历造成不稳定的顺序。五个方案分别验证预览、保存及穿戴，旧存档迁移与重复登录验证已有颜色不被清除。
- 回归验证使用内存角色及独立临时 SQLite，不操作真实玩家的好友关系。两位真实玩家的客户端申请提示和染色按钮交互仍需实机确认。

## 新账号默认昵称（local-sandbox-14）

- 首次创建角色基础资料即生成“旅行者 + 十进制 UID”，例如 `旅行者1000007`，各 UID 的默认昵称不同。
- 已存在但昵称为空的资料在登录读取时补齐并持久化；非空昵称原样保留。只更新昵称字段，保存失败时不伪造成功；并发改名时不覆盖已设置的名字。
- 登录时以内存角色和基础资料的昵称保持一致，避免旧角色存档中的空昵称覆盖补齐结果。游戏内正常改名仍走原有协议。
- 两个受影响账号补上昵称后，玩家已确认能进入游戏。本修复绕过空昵称触发的创建昵称界面链；该界面为何未弹出及“暂时关闭”提示的直接来源尚未确认。
- 回归测试使用隔离 SQLite 数据库，不创建真实测试账号、不修改在线玩家资料。

## 修复内容

- PlayerLogin 在访问数据库之前登记统一响应，数据库加载或反序列化失败时也回复失败，避免客户端一直等待；重连成功才执行重连后通知。
- PlayerMainData 失败时不继续发送入场通知；成功时将数据库已有的 Sex、HideValue、AccountType 写入响应。此项只修复字段映射，不推测历史账号缺失的渠道值。
- PlayerSceneRecord 对缺失 Data 的请求返回 BAD_REQ，避免空指针使游戏主循环停止。
- ChangeSceneChannel 在离开原房间前检查目的地，响应填写实际场景、房间号和好友目标；无效目标不移动玩家。
- 日志服务心跳保留客户端时间，同时返回独立的服务器毫秒时间。
- 正常关闭游戏主循环时强制保存所有内存玩家的最新快照，等待写入完成；失败尝试三次并向关闭调用方返回错误。关服不再受五分钟自动保存周期限制。
- 异步写库线程只向结果通道报告结果，游戏主循环更新保存状态；队列关闭与投递互斥，关闭时排空队列。数据库写入失败不推进成功保存时间。
- 玩家存档或数据库关闭失败时进程以非零状态退出，避免误报正常关服。

强制终止进程、任务管理器结束任务、会话清理、断电不会执行正常关服流程，仍可能丢失上次保存之后的变化。正常关服请在服务端前台窗口按 Ctrl+C，等待退出。不要在仍运行时复制 SQLite 文件作为一致性备份。

## 可复现构建

本机已有 Lolo、Resource、便携 Go 和配置时，在仓库根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\private-server\Build-Server.ps1 -TestOnly
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\private-server\Build-Server.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\private-server\Start-Server.ps1
```

Build-Server 固定检查上游提交，使用 server-patches/local-server.patch 修复源码，将 server-tests 下的测试复制到本地 checkout，运行 go test ./... 后才构建。已经应用补丁时不会重复应用；有冲突时中止，不覆盖用户源码。构建前备份原二进制到 backups。运行中的二进制不替换。源码回退点同样在本地 backups，补丁和测试位于未被忽略的目录，以便纳入本仓库版本管理。

自动化用例覆盖：缺失玩家的重连单次响应；空场景记录后仍可处理心跳；当前场景、另一房间、好友传送、缺失好友、非法房间；日志心跳的客户端时间回显和服务器时间窗口。存档用例使用临时 SQLite 文件，不读取或修改真实玩家数据库。
